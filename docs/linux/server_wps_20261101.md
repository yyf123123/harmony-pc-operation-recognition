## 服务器已经实际跑通

Ubuntu 22.04.5 / x86_64，WPS `12.1.0.17900`；利用已安装的 Xvfb、xauth、私有 D-Bus、xfwm4 和 X11/XTest。没有安装依赖、提权或连接他人桌面。首次软件许可/隐私协议经用户本轮明确授权接受，未登录或升级 WPS。

新建带 X 认证、关闭 TCP 的虚拟桌面，配置放在私有 XDG 目录，文档为新生成的随机文件名 DOCX。补充项目内最小 X11/XTest 辅助程序，读取真实焦点和窗口 PID；不伪造焦点。系统未安装标准 `xdotool`，辅助程序只覆盖本入口需要的命令。

| 阶段 | 动作语义通过 | 有效 Native 窗口 | 命中 | 触发至历史更新 |
| --- | --- | --- | --- | --- |
| 首次校准 | 3/3 | 3/3 | 保存、加粗；输入误判 NEW_DOCUMENT | 30.711 / 30.745 / 30.720 秒 |
| 独立重启后的自动重跑 | 3/3 | 3/3 | 保存、加粗；输入误判 ALIGN_CENTER | 30.607 / 30.606 / 30.585 秒 |

这两轮是三项功能检查，不能称为 18 类总体准确率。退出后已核对第二轮授权的 WPS 及其子进程均不存在。模型未改；Native SHA-256 为 `3d003893295f209e4bfb595b8483c978ceb06744c3f64756efe06053a057da15`。

文档成功证据是保存后的精确文本与显式加粗属性。输入/加粗的验证保存放在 Native 采样完全结束之后，不混入观察窗口。真值、预测分文件；Native 只接收随机事件 ID。

自动化入口为 `scripts/linux_server_desktop.py`；三项检查为 `scripts/linux_server_wps_smoke.py`，复用原 `opsctl serve` 和共用核心，不另写识别公式。启动提示曾导致两次文档核验失败，另一次因旧弹窗窗口 ID 已变化在采集前失败，均保留。已加入 Escape 取消普通提示、实际编辑→保存→撤销→保存核验空白的前置检查，重新绑定文档焦点后才开始。不会自动接受许可、升级或安装字体。

私有 profile 有互斥锁；目标只来自本入口创建的 WPS 进程树，准备阶段稳定后冻结初始 PID 集合，采集中变化仍立即失败。退出按 PID/启动身份清理本次进程组，不杀其他用户进程。

验证：8 项既有桌面/检查入口 Python 测试通过；服务器实际验证并发 profile 被拒绝、缺 DISPLAY 不返回伪焦点；X11 辅助程序在服务器编译并完成上述真实按键/文档检查。Native 核心与模型未改，本轮未重复整套跨平台构建。
