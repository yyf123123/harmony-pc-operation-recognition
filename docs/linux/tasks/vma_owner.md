## 目标

在新私有仓库的 `linux` 分支，将已有 Native 识别工程接入 Linux VMA 观测，并负责识别、操作历史、下一步预测与文件页标记的整体联调。

## 工作内容

1. 同步最新 main 并读取仓库规则、README、Native 适配说明和测试；核对 CMake 目标、公开 C++ API、模型包、特征 schema、标签版本及 SHA。先运行现有离线基线，不覆盖 Windows/OpenHarmony 入口。
2. 增加 Linux 采集适配器：读取目标进程 `maps/smaps`，按当前特征协议执行 `clear_refs` 与观察窗口；记录系统页大小、进程启动身份、焦点证据、子进程覆盖和权限错误。未经目标环境授权不自动提权，不自动清缓存或终止应用。
3. 对每个采样阶段记录单调时钟起止、采样开销和质量。必须按模型所需协议生成输入；若需要 action/post-action 两窗口，不能悄悄替换成单窗口。采集失败或进程重启不得伪装为零向量。
4. 复用现有 C++ 特征与类中心余弦匹配，保留 schema、2048 维与标签校验。与 Python 在同一批窗口和向量上对照，采用已有 `1e-9` 容差；差异定位到输入、特征或打分阶段。
5. 提供独立的操作事件接口，区分识别结果、真实标签与 UI 请求。按应用实例维护有界历史，以事件 ID 去重；实际重复操作不能仅因标签相同被合并。定义重启、会话结束、未知区间和乱序事件的处理。
6. 从新仓库及现有模块确认下一步预测模型的输入输出、词表与加载方式。使用显式标签映射接入；模型或词表缺失时报告未就绪，不用伪造预测替代。
7. 与璟雯对接操作—页映射，将预测转换为用户态候选标签；与欣彤统一反推方法接口。未预测到的页保持未知，不能全部判冷。
