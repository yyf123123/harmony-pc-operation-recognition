# 欣彤任务：其他反推方法接入与统一评估

## 目标

将已有其他操作反推方法接入统一 Linux 链路，使其能够与 VMA 方法在相同操作、相同时间窗口和相同会话上比较，并输出可供历史模块使用的识别事件。

## 工作内容

1. 列出现有方法、输入证据、Linux 依赖、输出粒度、延迟、权限与可识别标签；无法覆盖的操作显式标为不支持。
2. 采用新仓库标签或建立显式映射，输出方法 ID、模型/规则版本、事件 ID、应用实例、窗口、候选操作、分数语义、状态和质量。不要把原始相似度写成已校准概率。
3. 保持原始方法输出可追溯；把 UI 请求、采集真值和推理输入分开，防止自动化 label、文件名、trial ID 等泄漏到反推特征。
4. 在共同数据集上报告各方法的操作识别 Accuracy、Macro-F1、混淆矩阵、覆盖率、延迟与开销；按完整会话/trial 切分，说明失败和拒识样本是否计入分母。
5. 输出错误互补与冲突案例，先支持单方法选择与结果并列。需要投票、仲裁或平滑时，提出显式可配置方案，在验证集上确定策略；不默认改变 Native 基线行为。
6. 与 VMA 负责人测试事件去重、乱序、方法切换、会话重置和不可用处理，避免同一真实操作被多个方法重复写入历史。

## 交付

- 每种方法的 Linux 适配入口与统一输出适配器。
- 方法能力表、标签映射表、依赖与错误说明。
- 同一批独立测试会话上的横向评估与互补案例。
- 供整体联调使用的事件回放夹具，明确标识合成与真实数据。

## 验收

方法可以独立启停；失败可观测；输出能被历史模块消费；不同方法不会重复追加同一操作。各方法比较必须使用相同数据切分与时间边界。
