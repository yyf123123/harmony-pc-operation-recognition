# 慧京任务：Linux WPS 数据集采集与质量交付

首版任务已指定为[18 类批采规格](../batch_collection_v1.md)：先全类 2 轮预检，通过后自动进入 50 轮独立操作（900 有效样本），另采 30 个连续会话 × 20 操作（600），正式合计 1500。复用慧京已有自动化，不必等待仓库内全部 UI 原语。当前状态为待桌面预检，尚无正式数据。

仓库内统一启动器仍仅提供单操作/单窗口，批采开关未开放；外部自动化使用 README 中的 precondition/action/verify/focus 计划接口对接采集，不能把任务规格当作已实现的批采命令。[三项内置原语说明](../desktop_smoke.md) 仍可用于排查环境；对接和代码修复由 Codex 负责。18 类全通过前不扩大采集。

## 目标

依据 VMA 负责人提供的已验证脚本，采集能同时支持操作识别、下一步预测和操作—文件页映射验证的 Linux WPS 数据。

## 开始前必须收到

- 新私有仓库 `linux` 分支的具体提交号、构建/运行命令和环境要求。
- 冻结的 WPS 操作 ID、前置状态、动作步骤及成功判据。
- 一次完整 smoke 的示例输出、质量检查入口、采集窗口与异常处理说明。
- 璟雯提供的页级采集入口和权限要求；不能用 VMA 汇总数据代替页访问真值。

## 工作内容

1. 记录 Linux/内核、架构、系统页大小、WPS 版本、代码/模型/词表版本及设备匿名 ID，确认测试文档副本与唯一输出目录。
2. 先运行一个完整 smoke，检查 baseline/action/post-action 等当前模型规定的阶段、操作成功证据、时间戳、标签、向量和页访问关联。权限失败、阶段缺失、操作失败或维度错误时先修复，不直接扩大采集。
3. 采集独立操作样本：对覆盖操作重复执行，保留前置状态与文档信息，用于特征和操作识别验证。重复数先按小批试采的失败率、类别差异与采集成本确定。
4. 采集连续会话：采用多种合理办公流程与文档，保留真实操作顺序、间隔、失败和重试，不要所有会话都固定成同一操作轮回。
5. 与璟雯的采集同步，记录每个操作窗口中实际访问的文件页。采不到的范围和原因单独记录，不以空集合冒充没有访问。
6. 运行质量检查，隔离失败样本，输出样本数、类别分布、阶段完整率、页映射关联率和时钟异常。原始记录保留，派生数据可重新生成。
7. 按预先冻结的完整会话/trial 分组交付训练、验证和测试清单；同一会话的相邻窗口不得随机拆到训练和测试两侧。

## 交付

- 原始操作日志、VMA 窗口数据、页访问数据、环境与版本元数据。
- 特征/标签/样本索引、train/val/test 分组清单。
- 数据质量报告、失败清单、采集命令与可复现说明。
- 数据存储位置与摘要校验。数据进入约定的私有存储，不提交到旧公开仓库。

## 验收

每个有效样本均能关联真实操作、阶段窗口、进程身份与页级证据状态；连续会话顺序可恢复；失败样本不会伪装成成功记录。正式规模须在 smoke 通过后确定，不承诺未经试采验证的数据量或准确率。
