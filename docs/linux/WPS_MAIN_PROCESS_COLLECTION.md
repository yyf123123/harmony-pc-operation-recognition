# 给采集同事：WPS 主进程每 2 秒无标签采集

本入口对应 2026-11-03 用户确认的新需求：**只采指定 WPS Writer 主进程，每 2 秒一帧，连续约 30 分钟，前台自动化与采集互不通信。** 不采子进程，不按操作分段、不需要操作标签，不运行旧模型或聚类。目标是交付后续可重建特征的原始内存观测。

## 1. 环境与启动

Linux，Python 3.10+ 标准库即可；无需 pip、CMake、模型或原来的 fast 包。使用桌面普通账号，先启动 WPS 并打开专用测试文档副本。

用系统监视器确认 Writer 主进程 PID，并核对其可执行文件：

```sh
readlink -f /proc/实际主PID/exe
```

不要直接照抄 PID。脚本会核对 UID、可执行文件和 start_ticks，不扫描或读取子进程，也不会重启、终止 WPS 或提权。`--wps-executable` 必须填写上一步得到的真实二进制路径；默认值是 `/opt/kingsoft/wps-office/office6/wps`。

在仓库根目录运行（将 PID、版本和输出路径替换为本机实际值；输出父目录须已存在，末级目录必须全新）：

```sh
python3 scripts/collect_wps_periodic.py \
  --pid 12345 \
  --interval 2 --seconds 1800 \
  --app-version '实际WPS版本' \
  --output /已有私有数据目录/wps-main-本次唯一目录
```

也可只下载该 Python 文件，使用相同参数直接运行；它不导入仓库模块。

**建议先将 `--seconds` 改为 `60`，输出到另外的新目录预检，再启动 1800 秒正式采集。** 同事可在另一终端独立启动操作脚本，不需要向采集脚本发消息；也可手动连续使用 WPS。操作过程允许自然停顿与 idle，不用每做一个动作等采集。

X11/Xwayland 上如果已经有 `xdotool`，建议加 `--focus-x11`，记录每帧前后焦点。没加该参数时明确写入 `foreground_evidence=unknown`，不声称已证明 WPS 聚焦。该参数只观察窗口 ID/PID，不读标题；原生 Wayland 暂无焦点适配。前后两次焦点证据也不能证明整个区间始终聚焦。

## 2. 采样语义

- 使用单调时钟的绝对读取计划，目标每 2 秒读一帧；上一帧处理结束后重新清引用，再等下一读取时刻。保存实际 clear/read 起止、观测跨度、读取迟到和失败，不能把目标节拍当精确观测时长。
- 写 `clear_refs=1` → 观察 → 读完整 smaps；不在读取前再次清位。不要同时运行旧 fast、run/serve 或其他对该进程清引用的工具；本脚本的锁只阻止本脚本重复启动，不能替其他工具协调。
- 保存所有有效帧，包括空闲和低活动帧；失败保留状态，不补零。超过读取时间预算的帧标为无效，错过的时隙记录跳过，不密集补采。
- 进程退出、重启或可执行文件变化时停止，不自动绑定新 PID。子进程变化不影响此明确的主进程观测范围，也不会自动扩采。若有活动主要发生在子进程，该活动可能无法从本数据解释。
- Referenced 是近似区间引用证据，不能当精确访问次数或页列表。跨帧求和不是访问页并集。

## 3. 输出与交付

```text
本次目录/
  session.json          # 主进程身份、周期、环境、完成状态、CPU与数量摘要
  frames.jsonl          # 每个计划时隙的实际时序、质量与原始数据索引
  vma.jsonl.gz          # 逐帧逐VMA结构、全部kB字段、缺失字段和VmFlags
  quality_events.jsonl  # 失败与质量事件
  raw/*.smaps.gz        # 同一次读取的完整原始smaps
  manifest.json         # 文件长度与SHA-256
```

内存字段包含 Size/Rss/Pss/Referenced、Anonymous、私有/共享干净页与脏页、Swap，以及内核实际提供的页大小和大页字段；缺少可选字段明确标缺失，不填零。保留原始地址/offset/device/inode/path，后续特征不能直接使用 PID、地址或随机文档名当类别线索。

2 秒 × 30 分钟约有 900 个计划时隙，实际有效数查看 session.json。终端 `completed` 只表示到达计划结束；有效率、焦点、缺口、CPU与体积仍需查看文件。Ctrl-C 会保留已采数据并写 `interrupted`，中断后的目录不能当完整 30 分钟会话。30 分钟正式数据量与聚类效果尚待同事采集验证。

请将整个输出目录私下交付，不只发派生向量，也不要上传 GitHub。原始路径和进程信息属于私有采集数据；不采文档正文、内存内容、凭据或操作标签。

## 4. 与之前版本的区别

旧 fast 固定 500 ms，还包含实验分段/旧模型候选；旧服务器 v2 的“主进程”是只由主进程贡献特征，采集覆盖仍包含子进程。本入口是独立的 `linux.wps.main-periodic.v1` 原始数据采集 profile，按本次要求真正只读/清指定主进程，不复用旧分类指标。其他平台和旧受控入口不改变。

## 5. 本次实际验证（2026-11-03）

Linux Python 3.10 的9项相关测试全部通过，覆盖原始往返、哈希、主PID范围、重复采集互斥、身份变化、解析失败保留原始数据、有效零活动和中断记录。Mac只运行解析测试，真实/proc测试明确跳过。

真实 WPS Writer 12.1.0.17900 在带认证的隔离X11桌面完成60秒、2秒节拍检查：30/30帧有效，全部VMA记录只含指定主PID，30帧前后焦点均对应目标；独立键盘脚本的6次输入均在保存文档中核验。采集与helper合计平均约7.20%单核，最大读取迟到约2.62ms，全部文件清单哈希通过，WPS正常退出。本次RPC只用于采集前的测试应用/文档准备与采集后的退出，不是采集脚本依赖。

以上是单环境60秒软件/采集检查，不证明30分钟完整采集、其他电脑或自然操作聚类效果。此前两次普通GUI启动检查未通过可编辑文档前置校验，未进入采样，失败证据私下保留。原始数据、测试文档和逐帧报告均未公开。
