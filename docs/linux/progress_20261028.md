## 运行器计时与剩余验收

新的受控运行器会在结果中给出特征/推理/最终检查耗时；输出和历史更新完成后才能知道它们的耗时，因此通过 health 的 last_success_timing_ns 查询，结果发出前不填假值。输出失败或窗口失效时，不生成有效成功计时。

真实采集证据和离线重放来自不同执行环境，不能相加后称新版本的实测端到端时延。当前协议仅观察窗口就至少 30 秒；分类快不代表自由操作实时识别已解决。真实 WPS 在线、跨重启、RPC 观测负载迁移、自主分段及下一步预测提前量仍需桌面会话验证。

Python/Native：190 标签一致，向量最大误差 1.11e-16，分数最大误差 2.22e-15；模型参数没有重训或覆盖，默认模型没有切换。

## 本轮实现与验证证据

当前主线是 Linux M4：保存的 Linux 小试参数已显式接入同一 C++ 核心、CLI、持续运行器和新增 C ABI 创建函数；原 C ABI 结构布局、三个 frozen 模型与默认行为不变。显式 Linux profile 的窗口从清引用前起算，与训练采集协议一致；冻结入口保留原时钟。

- Linux Native 源码：`bc04d12`；server-lbz G++ 11.4 / CMake 3.22.1 / Python 3.10.12；四项 CTest 和原三应用自检通过。数据仅为 190 个已核验样本的必要 compact TSV，传输前后核对 SHA；未传真实文档、整个 ZIP 或标签到服务器。首个含 AppleDouble 的传输目录被哈希门禁拒绝，改用无扩展属性的清洁 payload 后才开始测量。
- Linux 计时：190 样本全量预热一次、测量五次，共 950 条；Native benchmark SHA-256 为 `822e54dbdf6c67f8e56f3ce542f47b1a3d0645e91385dac5100c83833bcb7650`。执行记录、向量、逐条计时和 JSON 统计在 Git 外的私有 `operation_reports/20261028-linux-wps-v1/linux-native-bc04d12/`。

- Mac：`8cd18b6` 上 84 项 Python 测试中 75 通过、9 项 Linux 依赖跳过；修正观察时钟后四项 CTest 通过。本轮新增桌面包装器六项合成契约测试与五项 Native/profile/计时测试共 11 项通过；模拟输出不进入准确率报告。
