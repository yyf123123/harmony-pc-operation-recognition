# 慧京：手动 WPS 操作识别演示

目标：你手动操作，Native 从内存观测输出一个操作，再保存对照日志。首版是约30秒受控窗口，尚不支持随时自由操作。无需自动化配置、RPC、NumPy或手工填写 PID。

## 最短操作

1. 将包解压到 Linux 虚拟机桌面用户可写的新目录；打开 WPS Writer 的测试文档副本。终端与 WPS 并排放置，确保能看见终端提示；停止原自动化及其他 clear_refs 采集器。
2. 在包目录运行 `./start_manual.sh`。若文件无执行权限，运行 `sh start_manual.sh`。Python 要求3.10+；使用 X11/Xwayland。包优先使用系统 xdotool，否则使用随包的真实 X11 查询工具。没有依赖时不自动安装，不使用 sudo。
3. 首轮先准备空白测试文档。在终端按回车，5秒内点击 WPS 文档正文。两次“静置”时不操作；看到“现在操作”后输入一小段文字，随后停手。进入后置采样后继续不操作，直到显示结果。
4. 结果出来后再回终端，填刚才操作的编号。下轮在采样前准备好文档，分别测试保存、加粗。测试加粗应提前选中文字，窗口内只按 Ctrl+B；测试保存应提前修改文档，窗口内只按 Ctrl+S。这些准备动作都在本轮采样前完成。
5. 结束后将终端打印路径下的 `feedback.zip` 私下发回。不要打包整个运行目录，不发文档。若误做多项、没操作或动作失败，按提示如实选择，不删除错误轮次。

默认三轮，顺序由你决定，程序不会把计划操作告诉识别器。初次只测输入、保存、加粗；若整个流程可用，再使用 `./start_manual.sh --rounds 6` 增加有限检查。实际键盘动作由你完成，程序只查询焦点与进程、采集内存、显示提示并输出日志，不点击或修改文档，不结束 WPS。

## 能看到什么

终端依次显示“静置1/2 → 静置2/2 → 现在操作 → 停止操作 → 识别结果”。蜂鸣用于提醒，若终端禁用了蜂鸣，以可见文字为准。操作段是15秒观察预算，不要求一直按键；完成一次操作后立即停手。

运行目录包含 `report.json`、`comparison.csv`、Native 结果和 health；回传 ZIP 仅带固定允许清单，不包含文档、原始 VMA 或设备截图。日志记录全部失败尝试、自报真实操作、预测、时序以及是否一致。手动标签属于本人自报，没有自动成功证据；显示的一致率不能称正式准确率。每轮 Native 独立启动，准备期间的动作不拼成自然连续历史。

默认仍使用慧京小试参数 `linux-wps-writer-pilot-20261023-v1`。服务器候选仅可显式使用：

```sh
./start_manual.sh --model-profile linux-wps-writer-server-20261101-v2
```

两种模型都不能保证输入识别。服务器候选的独立重启回放70.27%不能代表这台虚拟机；不要按预测正确与否筛选回传。

## 常见问题

- 当前焦点不是指定 WPS：确保用 Writer、点击正文，默认安装路径为 `/opt/kingsoft/wps-office/office6/wps`。自定义安装可追加 `--wps-executable /实际路径/wps`，不填 PID。
- 权限不足：使用启动 WPS 的同一个普通用户，保留报错反馈；不要将整个演示改为 root。
- 焦点/子进程变化：本轮会失败。下一轮重新选择当前覆盖，采样途中不会自动增补 PID。
- 预编译 ABI 不兼容：入口尝试使用已有 CMake/C++ 工具本地重建；缺编译器、X11 开发库时明确停止，不自动安装。
- 中途取消：Ctrl+C 只停止本次 Native 进程，不关闭 WPS；已完成或失败记录仍保存。
- 原生 Wayland 不支持当前焦点入口；不能伪造焦点，改用已有 X11/Xwayland 会话测试。

## 为什么本版不删5秒阶段

首版先让人验证手动提示、焦点与日志是否可用，沿用两次5秒基线、15秒操作、5秒后置。具体时长并非最优结论。建议后续保留完整对照，依次验证 `5+5+5+5=20秒`，再验证 `2+2+5+2=11秒`；这些是待测方案，尚未实现或证明有效，不包含在本测试包中。缩短要重新检查采样开销、动作完成率和跨重启识别。

删除第二基线会改变背景估计且当前核心要求至少两次；删除后置会改变 ACTION/POST 最大增量特征。两者可作为新协议研究，但不能把缺段伪装成完整样本，也不能将本版模型效果沿用到新协议。
