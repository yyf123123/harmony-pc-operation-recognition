# WPS 无标签 VMA 聚类：采集与入库要求

日期：2026-11-03。用户后续已确认2秒一帧，并指定本次只采WPS主进程。可执行入口与同事操作说明见[主进程采集](WPS_MAIN_PROCESS_COLLECTION.md)。本文件保留需求设计依据；下面通用方案中涉及完整子进程覆盖的条款不用于此次 main-process-only profile，未来扩采须另立协议。本次实现与实际验收范围以项目状态和上述操作说明为准。

用户最新目标：前台连续模拟真人使用 WPS；后台独立定时观察内存；不要求逐操作标签与操作边界；从观测特征聚类，归纳少数粗粒度模式。本协议适用于这条新路线。旧受控分类、手动演示与冻结模型保留原协议，不能把其结果作为本协议的效果证明。

## 1. 可直接替换原图片的要求

1. 前台在 WPS Writer 中执行连续、合理的办公流程，包含输入、编辑、格式、查找替换、表格、保存与文档管理等常见活动，允许不同长度的停顿和 idle。避免每个动作都重置为空白文档、固定长等待或按类别整块机械重复。不要求为每个动作生成训练标签。
2. 后台采集进程常驻，按独立单调时钟定时采集目标 WPS 应用实例及明确授权子进程的逐 VMA 数据。初始建议目标节拍为 **2 秒/帧**；每帧按“核验身份与覆盖 → 清引用 → 定时观察 → 读取 smaps → 再核验 → 保存”执行。必须保存清引用、读取和写出的实际时序及失败状态。2 秒须经小规模开销预检后冻结，不能当作已验证的最佳间隔。
3. 自动化与采集进程各自独立运行。采集不接收操作名、请求、动作起止或完成信号，不等待自动化 ready，不以动作日志触发、切窗或筛选样本。采集记录包含空闲、连续操作、混合窗口和异常，不能只留下活动片段。
4. 首轮正式观察约 **30 分钟**，另记准备与预检时间。2 秒目标节拍约有 900 个计划采样时隙，有效帧数以实测为准。原始帧全部保留，离线先比较单帧与非重叠 **10 秒统计窗口**，再聚类归纳大类。30 分钟是探索数据量，不保证聚类质量或跨启动泛化。

其中“常驻”指采集进程持续运行，不要求锁住内存，也不需要内核模块。10 秒改作可调整的分析窗口，不再同时承担未定义的观察时长与采样间隔。

## 3. 采样节拍与清引用

| 参数 | 初始建议 | 边界 |
| --- | --- | --- |
| 原始读取目标节拍 | 2 秒 | 预检后冻结；不是读取后再无条件 sleep 2 秒 |
| 开销不满足时的候选 | 5 秒，使用另一个 profile/会话 | 不在一个正式会话内悄悄自适应改频率 |
| 离线统计窗口 | 先用非重叠 10 秒 | 保留原始帧；可重新比较其他时长 |
| 准备/稳定观察 | 建议 60–120 秒，另记 | 保留其观测与阶段标记，不宣称已建立永久空闲基线 |
| 正式探索 | 约 30 分钟 | 包含自然 idle；不要求每个动作等待一次采样完成 |

采用单调时钟的绝对读取计划。上一轮读取与必要核验完成后，立即为下一轮清引用，再等到下一预定读取时刻。逐 PID 顺序清位、顺序读取不能视为同一瞬间；每个 PID 分别记录 clear/read 的开始与结束时间。实际观测跨度由这些时间确定，不强行写成精确 2 秒。

读取结束后的校验、写出与下一次清位之间也存在观测空隙，须记录。超时则记录错过的计划时隙，不并发读取、密集补采或补零；本轮失败后，重新完成身份核验和清位，才能建立下一完整观测。

写入 `clear_refs=1` 后才开始本轮观察，观察结束先读取 smaps，不能在读出前再次清位。读取 smaps 本身不完成这一步清位。`Referenced` 是当前被标记为引用/访问的内存规模；清位后的定时读数提供近似区间活动证据，不是精确访问次数、全部访问历史或逐页列表。[Linux clear_refs 接口说明](https://man7.org/linux/man-pages/man5/proc_pid_clear_refs.5.html)。

只有一个采集器负责清位；与其他 VMA、页位或文件页方法串行或通过独立的采集侧协调机制共享观测，不能各自清位。此协调不涉及自动化操作通知。该观测会改引用位，需测量采集干扰。

连续 5 个约 2 秒的 Referenced 统计可求均值/最大值等，但不能求和后称为“10 秒访问页并集”，也不等价于只在 10 秒开始清一次引用。跨进程的共享页同样可能重复计数。

## 4. 必须留存的数据

原始观测单位为 `(session_id, frame_id, pid, start_ticks, VMA)`。下列字段用于留存，不代表全部送入聚类。

| 层级 | 采集内容 | 用途 |
| --- | --- | --- |
| 会话 | 数据 schema、完整 capture profile、采集程序版本/哈希、应用版本、内核/架构、实际基础页大小、时钟单位、启动与结束状态 | 复现与隔离不同协议/环境 |
| 应用与进程 | 应用实例 ID、主 PID、每个授权 PID 的 PPID/start_ticks/状态/规范化角色；覆盖版本及新增/退出记录 | 防止 PID 复用、漏采子进程或混合不同启动 |
| 每帧时间 | 帧序号、计划读取时刻、逐 PID clear/read 起止、核验起止、写出完成、实际跨度、迟到量与帧间空隙 | 区分目标间隔、实际观测与处理开销 |
| VMA 头 | 起止地址、权限、文件 offset、设备号、inode、pathname、段类型 | 语义归并与映射变化诊断 |
| VMA 内存值 | `Size`、`Rss`、`Pss`、`Referenced`、`Anonymous`、`Private_Clean`、`Private_Dirty`、`Shared_Clean`、`Shared_Dirty`、`Swap` | 同时保留活动、驻留规模与内存构成 |
| 页与映射属性 | `KernelPageSize`、`MMUPageSize`、`VmFlags`；内核提供时保留 `AnonHugePages`、`FilePmdMapped`、`ShmemPmdMapped`、Hugetlb 等原始字段 | 避免固定 4 KiB 假设，解释大页与共享映射差异 |
| 焦点证据 | 当前窗口 ID、所属 PID、来源、检查时刻、覆盖结果或失败原因 | 标识目标是否前台；不保存窗口标题或正文 |
| 质量与成本 | 每 PID/帧成功状态、错误码、缺失字段、覆盖变化、超时、原始文件路径/哈希/长度；采集及 helper CPU、RSS、磁盘增长 | 发现采集失败与观测干扰 |

优先保留每次同一读取产生的完整 smaps 文本，压缩后在 Git 外保存，并从该份文本解析。smaps 的 VMA 头已经包含 maps 结构信息，不必每帧额外读取 maps 再与另一时刻的 smaps 强行拼接；`smaps_rollup` 仅是进程汇总，不能代替逐 VMA 信息。读取过程存在映射变化竞争，起止记录和解析校验不能宣称是全进程原子快照。[Linux proc 文档](https://docs.kernel.org/filesystems/proc.html)。

预检生成字段能力清单。VMA 头、`Size/Rss/Referenced` 缺失或非法时，该 PID/帧无效；其他字段不可用时保存明确缺失状态，并禁用依赖它的特征，不能填成 0。保留原始单位与数值，派生时统一换算为字节；PSS 等比例量不按整数页向上取整。基础页数与大页数量分别说明。[smaps 字段说明](https://man7.org/linux/man-pages/man5/proc_pid_smaps.5.html)。

可附加 `/proc/PID/stat` 的 CPU/缺页计数作为诊断上下文；第一版聚类仍先限定内存特征，避免不经比较就引入控制方式或系统负载捷径。不采内存正文、`cmdline`、`environ`、凭据或真实文档内容。

## 5. 进程覆盖与异常

1. 采集前明确授权主 PID/启动身份和所需子进程，记录全部覆盖。可分别计算主进程与角色汇总特征，但不能因只用主进程特征而省略子进程采集或忽略失败。
2. 覆盖变化时记录 added/removed、父进程、名称、start_ticks 和时间；当前帧标为不完整。新增进程先按既有规则只做身份诊断，不默默清位或扩展访问权限。
3. 在后续安全边界重新核验授权集合并开启新 coverage epoch，才能恢复完整帧；未恢复期间记录缺口。旧有效段保留，跨覆盖变化的差分与统计窗口无效，不把前后拼成连续完整观测。
4. 主进程退出/重启结束当前应用实例；新实例建立新会话。PID 一样但 start_ticks 不同仍是不同实例。
5. 前后台切换与焦点未知分别标记。第一版 WPS 前台聚类排除这些窗口，但原始记录保留；不把“焦点失败”填成“空闲”。边界检查不能证明两次检查之间始终聚焦。
6. 稳定收集空闲帧，不因特征全零、活动低或没有候选而删除。权限/解析/超时失败与有效零活动严格区分。

## 6. 自动化独立性与特征构造边界

- 两个进程可由人先后启动，采集按自己的固定时长结束。自动化不按采样节拍安排动作或等待采集完成；采集不查询自动化状态。初版不需要逐操作分段器、开始/结束阈值或逐操作标签表。
- 自动化可独立保留版本、随机种子、整体完成状态与流程覆盖摘要，用于检查是否跑完预期流程；不要求逐动作标签，不作为聚类输入。脚本尝试过某动作不等于已独立验证其语义成功。
- 准备与额外语义核验在正式采集前后做，避免为了核验而额外保存、读文本或发 RPC 混进数据。正常流程中的保存仍保留。UI 键盘与 RPC 控制方式分别记录和审视，不能把 RPC 开销直接解释为用户行为特征。
- 新特征优先比较每帧各语义 VMA 的 Referenced 水平、RSS/PSS/脏页/匿名内存构成，以及同一覆盖内相邻帧的有符号变化；10 秒窗口再汇总均值、最大值、波动等。保留全量规模信息，不能只交 L2 向量或裁去负变化。
- 原始地址、PID、start_ticks、帧号、时钟、session/document ID、随机文件名、操作名及自动化计划不得进入特征。语义键做稳定归并；文档路径或临时路径须防止编码会话、操作或样本编号。
- 文件映射可能含匿名/COW 页；映射类别与 `Anonymous` 数值分别保留，不能只凭 pathname 推断物理页构成。新特征另立 schema，不覆盖原 2048 维模型协议，不假定旧类中心仍可使用。
- 先用非重叠统计窗，跨缺口/覆盖变化/重启的窗不填补。未来若用重叠窗，必须按完整会话隔离评估，不能随机打散相邻窗。
- 类数与类名根据数据确定，不预先将旧 18 类合并为监督标签。仅有内存证据时先称“内存活动模式”；检查是否主要按文档、应用启动、运行时长或控制方式分群，再讨论行为解释。

## 7. 入库/文件交付结构

可以使用 SQLite 索引，也可以先用有 schema 的 JSONL/TSV；本要求不强制数据库产品。原始压缩 smaps、索引与派生数据分层保存。

| 表或索引 | 主键/关联 | 主要内容 |
| --- | --- | --- |
| `sessions` | session_id | profile、环境、应用实例、版本、时钟、完整/中断状态 |
| `process_epochs` | session_id + coverage_epoch + PID/start_ticks | 授权范围、角色、覆盖起止与变化 |
| `frames` | session_id + frame_id | 计划/实际时刻、逐帧质量、焦点、完整性 |
| `process_samples` | frame_id + PID/start_ticks，并关联 session | 逐 PID clear/read/校验时间、原始路径/哈希、采样状态 |
| `vma_observations` | process_sample_id + region_index | VMA 头、全部内存值、单位与字段缺失状态 |
| `quality_events` | 独立事件 ID，关联 session/frame/进程 | 权限、退出、覆盖变化、解析/写出失败、错过时隙 |
| `feature_windows`（后续派生） | window_id + feature_schema + 来源帧集合 | 可重建特征、有效性、变换版本；不要求 operation_label |

失败尝试同样占帧序号并留状态，不能因只入库成功数据而消失。原始写出与索引提交须可核验，截断/缺文件不能成为有效帧。按帧记录哈希，最终生成交付清单。保留合法的全零观测与所有失败证据；不伪造标签来适配旧的 labels.csv 导出器。

30 分钟数据量用预检测得的“每帧原始/压缩字节 × 计划帧数 + 索引”估算，不预先承诺固定包体积。真实路径、原始数据与设备元数据按私有数据管理，不进入公开仓库。

## 8. 预检、报告与下一步

先在独立测试会话做约 5 分钟预检，包含约定的空闲与混合操作。初始 2 秒方案若开销不满足，再用另一个会话检查 5 秒；不同时启动两套 clear_refs 采集器。以下是建议的采集工程门槛，不是历史实测结论或聚类效果保证：

- 有效帧占计划时隙至少 95%；全部失败和跳过时隙可解释。10 秒派生窗第一版要求来源帧完整。
- 每帧清位、读取、核验等主动采集工作的 P95 墙钟不超过目标周期的 20%；分别记录阶段，不重复相加嵌套计时。另报写出时间、读取迟到 P50/P95、最大连续缺口和逐 PID 时间偏斜。
- 采集器及其 helper 的合计 CPU 平均目标不超过 10% 单核；同时报告 WPS 资源与响应干扰。通过与不采集的串行对照区分程序成本和 WPS 额外成本，不把虚拟桌面结果当真人体验验证。
- 原始文件完整、哈希/索引/帧数关联一致，关键字段全；覆盖与权限错误不隐瞒。磁盘空间按实测增长率预留。

门槛失败先检查重复焦点查询、频繁外部进程创建、重复 smaps 读取或同步写盘；必要时另立更慢 profile。不要只为达到通过比例删除异常帧。

首轮一段约 30 分钟用于判断数据与聚类是否值得继续。若要宣称可跨启动使用，后续至少补独立重启会话，并对文档/流程顺序作变化；开发与评估按完整会话隔离，变换参数与聚类中心在开发会话拟合后冻结。单会话内轮廓系数或图形分离不替代独立会话稳定性证据，也不能计算逐操作准确率。

当前需要实施的改动：新周期 profile 与调度器、同次读取的完整原始/扩展字段留存、逐 PID 时序和覆盖 epoch、无标签索引/质量报告、独立自动化入口及离线特征/聚类。旧 `run/serve`、500 ms watch 或现有四阶段侧录均不等于本协议已实现。

以上设计阶段仅核对本机代码/报告。后续按用户指定实现的2秒主进程采集及短时实测另见[运行说明](WPS_MAIN_PROCESS_COLLECTION.md)，不把设计阶段的完整子进程方案写成已实现。未重训模型或验证聚类效果。
