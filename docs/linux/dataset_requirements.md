# Linux WPS 数据集要求

## 三类用途，共享关联键

| 子集 | 核心记录 | 用途 |
| --- | --- | --- |
| 独立操作 | 真实操作、前置状态、成功证据、模型所需完整窗口及 VMA 数据 | 操作反推与特征验证 |
| 连续会话 | 多条合理办公流程的真实操作顺序、间隔、文档和失败事件 | 下一步预测与端到端验证 |
| 页级观测 | 操作窗口内实际访问的文件页及观测覆盖/错误 | 建立并验证操作—页映射 |

三者尽可能在同一会话同步采集，使用统一的会话、应用实例、操作实例与窗口 ID。独立操作数据不能冒充自然操作序列；请求执行不等于操作成功。

## 采集前冻结

1. 从新仓库读取 WPS 18 类操作及标签版本，区分当前 Linux 已实现与暂未覆盖项。旧目录若不同，提供显式映射，不直接重编号。
2. 定义每类操作的前置状态、执行步骤、成功判据和清理步骤。
3. 核对现有模型窗口协议、baseline 算法与特征公式，记录所有时间配置。若改变窗口或特征，升级协议并重新验证，不能继续冒用原模型准确率。
4. 选择测试文档副本和多种连续流程；记录文档标识、内容版本和大小，避免单一固定文件/流程形成捷径。
5. 划分完整会话/trial；测试集不参与阈值、平滑、融合和映射规则选择。

## 每个会话的最小交付结构

```text
<session_id>/
  metadata/     # 环境、代码/模型/词表版本、窗口配置、文件身份
  raw/          # 操作日志、VMA 窗口、页访问、成功证据
  derived/      # 特征、标签、样本索引、映射
  validation/   # 质量检查、失败记录、摘要校验
  reports/      # 数据质量与评估
```

原始记录保留，派生数据可重建。输出目录唯一，不覆盖历史运行。不要把真实文档、截图、运行日志或模型数据提交到旧公开仓库。

## 质量门槛

- 通过一次完整 smoke 后才扩大规模。
- ID 唯一且关联有效；操作起止、窗口起止及扫描耗时可检查。
- 向量维度与 schema 一致；非有限数、缺失阶段、权限失败与进程退出单独判定。
- 页访问的观测覆盖和失败有显式状态；未知不能填为“没有访问”。
- 类别分布、有效/失败数量、完整阶段比例和跨表关联率均有报告。
- 训练、验证、测试按会话/trial 隔离；同一会话的相邻窗口不跨集合。

## 评估项

操作识别：Accuracy、Macro-F1、各类召回与混淆矩阵，附未知/失败比例。

下一步预测：Top-1/Top-K、MRR，并分别报告真实历史输入与识别历史输入的结果。

页面候选：在独立会话上的访问命中率、召回、覆盖、候选页数量、失效/身份不明比例。

系统链路：采样、特征、识别、预测和映射查询的耗时及资源开销；Linux 离线、Linux 真实采集和 WPS 实时状态分别呈现。
